
Vite 本地端口为 5174。开发环境将 `/api` 代理到后端 8080，将 `/opentalking` 代理到本机数字人服务；生产环境由 Nginx 执行相同职责。

## 3. 前端约定

- 页面放在 `src/pages/`，通用布局和可复用交互放在 `src/components/`，请求、会话、主题等基础能力放在 `src/lib/`。
- 受保护路由必须先读取当前登录资料，再根据角色限制候选人端和管理端入口。
- 所有 API 走同源 `/api`，不要在组件中硬编码后端主机、端口或外部密钥。
- 主题状态存放在浏览器 `localStorage`；其中只能保存非敏感偏好，不能保存 API Secret 或长期凭据。
- 对话框应使用可访问组件并处理焦点、关闭和键盘交互；动态图表使用 SVG 时应提供语义标签。

### 界面文案与图标规范

- 界面文案使用正式、简洁的中文；同一状态和操作必须保持相同名称，例如统一使用“报告已生成”“正在创建…”“返回工作台”。
- 错误提示应说明失败对象并给出可执行建议，例如“候选人列表加载失败，请稍后重试。”；不要直接向用户展示内部实现名或异常堆栈。
- 加载状态统一使用“正在 + 动作 + …”，空状态使用“暂无 + 对象”；按钮使用明确动词，不使用“点一下”“再来一次”等口语表达。
- 图标统一使用 Lucide React。一个图标保持稳定业务语义，禁止使用星光等装饰图标代替报告、训练、虚拟人或模型服务。
- 常用语义映射：`BrainCircuit` 表示大模型，`Bot` 表示虚拟人，`FileUser` 表示简历，`FileChartColumn` 表示评测报告，`ListChecks` 表示训练计划，`CalendarCheck2` 表示面试记录，`RefreshCw` 表示刷新或重新生成。
- 纯图标按钮必须提供 `aria-label`；对话框必须提供 `role="dialog"`、`aria-modal="true"` 和可关联的标题。

## 4. 媒体与浏览器能力

- 摄像头、麦克风和语音能力依赖安全上下文：生产使用 HTTPS，本地可使用 `localhost`。
- 浏览器自动播放可能被拦截；数字人或语音播放需要由一次用户点击触发恢复。
- 组件卸载、路由跳转和异常中断时，停止录音、播放器和数字人会话，避免麦克风占用与并发泄漏。
- `mpegts.js` 只处理适合它的流协议；WebRTC/XRTC 应使用对应的 SDK 或播放器。

### 面试方式与录制状态机

- 面试房间加载后先显示不可绕过的方式选择，不自动调用浏览器朗读题目；选择一旦写入服务端不能更改。
- `TEXT` 不获取录制权限。点击“重读题目”时：虚拟人已运行则由虚拟人播报，否则调用浏览器 Web Speech API。
- `AUDIO` 只获取麦克风；`VIDEO` 获取麦克风和目标 1280×720、15fps 的摄像头流。两者使用 `MediaRecorder` 生成 WebM，并在每道题完成时停止、上传再切换下一题。
- 录制模式在前端禁用题目列表、上一题和下一题，后端进度接口也只允许“当前题已保存后进入下一题”，不能依赖前端按钮作为唯一约束。
- 录制上传失败时保留当前页面内的待上传分段，联网后自动重试；用户主动结束时若仍有失败分段则阻止结束。刷新或强制关闭可能使正在录制但尚未结束的当前题分段丢失，因此上线验收必须覆盖异常退出提示。
- 管理端回顾通过带 JWT 的 Blob 请求读取受保护媒体，按题选择录制分段，并展示同题的题目、回答、追问与过渡事件；点击事件会换算为分段内相对时间并定位播放器。

## 5. 发布检查

1. 执行 `npm run build`，TypeScript 与 Vite 构建都必须成功。
2. 验证登录、角色跳转、候选人面试、报告与管理端核心页面。
3. 验证 `/api`、`/opentalking` 的同源代理，不在浏览器控制台暴露第三方密钥。
4. 验证深色模式、窄屏布局、键盘可操作性和自动播放/麦克风失败提示。
5. 分别验证文字、语音、视频三种模式；视频使用浏览器 `MediaStreamTrack.getSettings()` 核对实际分辨率/帧率，设备不支持目标参数时应有明确提示。
6. 验证每题切换前录制上传完成、录制中无法主动切题、刷新后重新授权，以及管理端按题播放和媒体对象 URL 释放。
