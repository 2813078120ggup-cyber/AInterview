# AI 与 OpenTalking 知识库

> 更新日期：2026-08-04
> 范围：仅记录当前保留并实际接入的 AI 与数字人能力。

## 当前能力

| 能力 | 当前实现 | 说明 |
|---|---|---|
| AI 面试官 | DeepSeek Provider、版本化提示词、异步 AI 任务 | 负责题目分析、评分、报告和追问 |
| OpenTalking 数字人 | 同源 `/opentalking` 代理、WebRTC、TTS Provider | 当前唯一保留的虚拟人运行时 |
| 浏览器降级朗读 | Web Speech API | OpenTalking 不可用或用户未授权时的本地降级 |

## 调用边界

1. 前端通过 `/api` 访问 Spring Boot，通过 `/opentalking` 访问 OpenTalking 服务，不直接暴露第三方密钥。
2. 后端 `/v1/virtual-human/sdk-config` 只返回已启用且配置完整的 OpenTalking Provider 配置。
3. OpenTalking 负责数字人媒体会话和 TTS；AInterview 负责题目、回答、追问状态及持久化。
4. 面试房间的题目朗读、简短提示和结束语都复用同一个 OpenTalking 会话，避免文本来源分叉。
5. OpenTalking 会话不可用时，页面可降级到浏览器朗读，但不会重新启用已停用的讯飞 SDK 或客户端。

## 配置要点

- Provider 类型：`virtual-human`
- Provider 编码：`open-talking-virtual-human`
- Base URL：OpenTalking 服务地址，例如本地 `http://127.0.0.1:8000`
- 模型：填写已部署的 OpenTalking 模型，开发环境可使用 `mock`。
- Avatar ID：填写 OpenTalking 服务实际可用的形象标识。
- APP ID：填写 TTS Provider，默认使用 `edge`。
- API Key、API Secret：OpenTalking 本地链路不使用，保持为空。

## 排障顺序

1. 在系统设置中确认 OpenTalking Provider 已启用并设为语音默认。
2. 检查 `/opentalking/health`、同源代理和 WebRTC 网络连通性。
3. 检查模型、Avatar ID、TTS Provider 是否与 OpenTalking 服务端一致。
4. 面试页面重新连接数字人后，再执行题目朗读或语音回答。
5. 如果仍无法建立媒体会话，先使用浏览器朗读完成面试，并保留浏览器控制台与服务端日志。
