# 数据与安全知识库

## 1. MySQL 8 与 MyBatis-Plus

项目使用 MySQL 8.0、InnoDB、`utf8mb4` 和 `utf8mb4_0900_ai_ci`。实体通过 MyBatis-Plus 的 `@TableName`、`BaseMapper` 和条件构造器访问数据库。

- 优先用 `LambdaQueryWrapper` 表达条件，减少字段改名导致的字符串错误。
- 软删除字段由 MyBatis-Plus 注解管理；查询和唯一约束设计时要考虑已删除记录。
- 多表状态变更、注册、报告生成等需要事务的操作使用 Spring `@Transactional`。
- 结构和字段含义以 [数据字典](../database/data_dictionary.md) 为参考，最终以当前 Flyway 迁移为准。

## 2. Flyway 数据库迁移

运行时唯一迁移目录是：

```text
backend/src/main/resources/db/migration/
```

当前迁移集合为 V1、V9–V26：空库执行 V1 完整基线后继续执行后续迁移；既有非空库首次接入时按 V8 建基线，再继续执行 V9–V26。V18–V20 覆盖进度恢复、录制时间轴和面试心得，V21–V24 覆盖算法练习中心及题库模板对齐，V25 新增反馈工单/站内通知，V26 新增学习资料、PDF 版本、权限和批注。媒体文件本体仍保存在媒体存储目录，执行记录存储在 `flyway_schema_history`。

新增结构变更的规则：

1. 下一次变更从 V27 起在运行时迁移目录新增 `V<版本>__<英文描述>.sql`。
2. 已发布迁移的文件名和内容不可修改；修复用新的更高版本。
3. 本地验证 `validate`、`migrate` 和 `flyway_schema_history` 后再部署。
4. SQL 只保存在当前有效目录；历史归档脚本未迁入本仓库，也不参与执行。

完整步骤见 [数据库脚本与 Flyway 迁移指南](../database/README.md)。

## 3. Redis

Spring Data Redis 用于运行时缓存、验证码冷却等需要快速访问且可跨浏览器会话保存的状态。Docker 使用 Redis 7.2 Alpine，并启用 AOF 与密码认证。

- 生产环境必须设置 `REDIS_PASSWORD`，不向公网直接暴露 Redis。
- 缓存键需要带业务前缀、用户或目标标识和 TTL，避免相互覆盖与无限增长。
- 缓存只能加速或协调流程；关键业务结果仍需落到 MySQL。

## 4. 身份认证与授权

| 技术 | 用途 | 注意事项 |
|---|---|---|
| Spring Security | 无状态安全过滤链、方法级权限控制 | API 使用 `STATELESS` 思路，不依赖服务端 HTTP Session。 |
| JJWT 0.12.6 | 签发和解析访问 JWT | `JWT_SECRET` 至少 32 字符，生产环境使用随机高熵密钥。 |
| BCrypt | 密码哈希 | 只存哈希，绝不记录或回传明文密码。 |
| RBAC | 用户、角色、权限关联 | 管理端接口显式校验管理员权限，资源访问还需校验归属。 |
| Refresh Token | 刷新登录态 | 可撤销、可过期，避免将长期访问权放进短期 JWT。 |

## 5. 秘密与隐私

- Provider 配置中的敏感字段在后端加密保存，前端仅展示掩码；提交星号不能覆盖原值。
- 简历、回答和手机号属于敏感业务数据。AI 审计仅记录版本、模型、耗时、Token、状态和失败原因，不记录完整正文。
- 学习资料 PDF 及其媒体对象保存在私有媒体卷；资料必须处于已发布状态且当前用户拥有有效查看权限才能读取，下载还需满足资料下载开关。PDF 批注按资料版本和批注所有者隔离，默认仅本人可见。
- TLS 私钥、数据库卷、Redis 卷和生产 `.env` 均不提交 Git。
- 任何排障输出都应先做脱敏，再发送到日志或工单。
