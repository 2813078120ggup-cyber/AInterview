| JUnit / Spring Security Test | Spring Boot Test 依赖 | 后端与安全相关测试。 |

## 2. 分层约定

```text
Controller  →  接收 HTTP 请求、校验 DTO、返回 ApiResponse
Service     →  业务编排、事务、权限后的领域规则
Mapper      →  MyBatis-Plus 数据库访问
Domain      →  表映射实体
Config      →  应用属性、Security、第三方服务配置
```

- Controller 应保持轻量，不直接拼装 SQL 或处理密钥。
- 写操作由 Service 控制事务边界；跨表写入、状态变更和幂等逻辑必须在此层完成。
- API 成功响应使用统一的 `ApiResponse`，异常由全局异常处理器转换为规范响应。
- 分页接口使用项目的 `PageResult`，避免把 ORM 分页对象直接暴露给前端。
- 学习资料模块位于 `learning/`，由 Service 统一编排资料版本、私有媒体、用户/角色权限和批注；PDF 内容、下载与批注都必须在后端重新鉴权。

## 3. 运行与构建

```powershell
cd D:\Ainterview\backend
mvn test
mvn spring-boot:run
mvn clean package
```

Docker 采用两阶段构建：第一阶段使用 Maven + Eclipse Temurin 17 编译 JAR，第二阶段使用 Java 17 JRE 运行。运行容器使用非 root 的 `appuser`，媒体文件放在 `/app/data/media` 挂载卷中。

## 4. 配置管理

- 默认配置：`backend/src/main/resources/application.yml`。
- 环境差异通过环境变量覆盖，例如 `DB_URL`、`DB_USERNAME`、`REDIS_HOST`、`DEEPSEEK_API_KEY`。
- 不要把生产配置写进 Git；以根目录 `.env.example` 作为变量清单。
- 日志与接口错误不得输出密码、JWT、API Key、API Secret、签名 URL、完整简历或作答文本。

## 5. 开发检查清单

1. DTO 使用 `@Valid` 和合适的校验注解；错误信息不能泄露内部细节。
2. 权限接口使用 Spring Security 的方法级授权，并验证候选人只能访问自己的资源。
3. 外部 HTTP 调用必须设置超时、处理非 2xx 状态，并将失败转换为可诊断的业务错误。
4. 新增配置项时，同时更新 `.env.example`、部署说明与本知识库。
5. 修改后至少执行 `mvn test`；涉及接口契约时同步更新 API 文档。
