# 外部服务与文件知识库

## 1. Java HttpClient

项目使用 JDK 自带的 `java.net.http.HttpClient` 调用 DeepSeek、Provider 连通性检查和部分第三方 HTTP 服务。

- 创建客户端时设置连接超时；每个请求设置业务超时。
- 统一处理网络异常、超时、线程中断和非 2xx 响应。
- 认证信息仅放在后端请求头或后端签名 URL；日志中必须脱敏。
- 外部服务的错误应转换为用户可理解、可重试或可定位的业务错误，不直接回显原始响应。

## 2. 短信与邮件验证码

| 服务 | 配置 | 用途 | 注意事项 |
|---|---|---|---|
| 阿里云市场短信接口 | `REGISTER_SMS_HOST`、`REGISTER_SMS_PATH`、`REGISTER_SMS_APP_CODE`、`REGISTER_SMS_TEMPLATE_ID` | 注册短信验证码。 | AppCode 是敏感凭据，不进入前端和 Git。 |
| QQ SMTP | `MAIL_HOST`、`MAIL_PORT`、`MAIL_USERNAME`、`MAIL_PASSWORD`、`MAIL_FROM` | 邮箱验证码。 | 使用 `smtps`；密码/授权码只放运行环境。 |
| Redis / MySQL | 验证码状态与账户信息 | 冷却时间、验证码校验、刷新后仍有效的状态。 | 服务端强制冷却，不能只依赖前端倒计时。 |

验证码接口要限制发送频率、过期时间和目标格式；响应不能泄露“手机号/邮箱是否已经注册”等不必要的账户枚举信息。

## 3. 文件解析与媒体存储

| 技术 | 用途 | 项目约定 |
|---|---|---|
| Apache PDFBox 3.0.3 | 提取 PDF 简历文本 | 对无文本层/受保护 PDF 返回明确提示，不把文件内容写进错误日志。 |
| Apache POI OOXML 5.3.0 | 读取 DOCX 简历 | 限制文件大小和解析耗时，防止异常文档拖垮服务。 |
| JDK 文件 API | TXT / Markdown 和本地媒体处理 | 统一 UTF-8、路径规范化与异常处理。 |
| Docker volume | `/app/data/media` | 通过 `MEDIA_STORAGE_ROOT` 配置，容器重建后保留媒体文件。 |
| MediaRecorder + WebM | 语音/视频面试录制 | 浏览器按题生成音频或 720p/15fps 目标视频分段；后端流式落盘，默认单分段上限 100MB。 |

上传链路应至少校验：文件大小、扩展名、MIME 类型、实际可解析性、文件名净化与访问归属。不能直接用用户上传的文件名拼接磁盘路径。

## 4. 浏览器媒体与语音

- 摄像头/麦克风基于 `MediaDevices`，需要 HTTPS 或 localhost 和用户授权。
- 浏览器朗读属于 Web Speech API 客户端能力，后端 Provider 测试不应将其误判为服务端连通失败。
- 数字人、TTS、录音与视频流需在组件卸载时清理；失败时提供继续答题或文字交互的降级方案。
- 面试录制只采集候选人授权的麦克风/摄像头流；虚拟人 XRTC/WebRTC 媒体保持独立，通过题目、追问和过渡事件对齐时间轴，不直接复制进候选人录制文件。
- 本地 `media_data` 适合当前阶段，但必须根据并发数、面试时长、码率和保留天数做容量预算。生产规模增长时迁入私有 OSS，启用加密、生命周期与授权下载。

## 5. 外部服务排查顺序

```text
环境变量是否存在且格式正确
        ↓
服务地址/证书/DNS/网络是否可达
        ↓
凭据、服务套餐、模板或授权资源是否有效
        ↓
请求超时、HTTP 状态和错误体（脱敏后）
        ↓
业务降级与重试策略是否符合预期
```
