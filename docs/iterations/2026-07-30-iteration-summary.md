# 2026-07-30 项目迭代总结

> 迭代日期：2026-07-30  
> 项目名称：AInterview  
> 代码库数据库版本：Flyway V19  
> 生产数据库版本：Flyway V17  
> 发布状态：V17 已部署；V18–V19 及本迭代其余未发布改动仍需生产验收

## 1. 迭代目标

本次迭代围绕面试流程可靠性、语音/视频录制、AI 配置一致性、安全运维基线、前端表达与项目文档治理展开，重点解决以下问题：

- 追问达到上限后仍继续提问，以及追问表达重复、僵硬的问题。
- 页面刷新、网络中断和重复请求导致的进度或答案不一致问题。
- 面试开始前无法选择文字、语音或视频方式，缺少按题录制和回放时间轴的问题。
- 管理端已配置 DeepSeek，但报告生成仍只读取环境变量的问题。
- 首次进入视频面试时摄像头预览黑屏的问题。
- Flyway 文件来源不统一、历史 SQL 分散、部署与服务器资料缺少统一入口的问题。
- 前端品牌、文案、图标和标题字体不统一的问题。

## 2. 已完成内容

### 2.1 面试追问与流程可靠性

- 每道主观题的最大追问次数统一为固定 3 次，前后端采用一致口径。
- 达到第 3 次追问上限后使用确定性收尾语并自动进入下一题，不再调用模型生成可能包含新问题的过渡内容。
- 追问携带最近 8 条同题上下文，并增加重复度、越界、多问题和题目相关性校验。
- 追问校验失败时只重试一次，仍不合格则使用确定性兜底内容。
- 追问请求使用题目与轮次幂等键，忽略切题、结束或收尾后迟到的旧结果。
- AI 处理中禁止切题，题目朗读、追问和收尾消息分别标记，收尾语不计入追问次数。

### 2.2 面试进度与答案保存

- Flyway V18 新增面试当前题号和进度更新时间持久化。
- 题号和剩余时间由服务端恢复，前端每 15 秒进行校准。
- 页面刷新后继续轮询未完成的 AI 任务，不重复创建同一轮追问。
- 答案增加草稿、保存中、已保存、失败和离线状态。
- 保存失败自动重试两次，恢复联网后自动补交，并支持手动重试。
- 存在未保存答案、正在保存或待重试内容时，阻止切题或直接结束面试。

### 2.3 三种面试方式与录制时间轴

- 进入面试房间后先选择文字、语音或视频面试，不再自动朗读题目。
- 文字面试不录制；点击“重读题目”时由浏览器朗读，启动虚拟人后改由虚拟人朗读。
- 语音面试按题录制麦克风；视频面试以 1280×720、15fps 为目标录制摄像头和麦克风。
- 录制模式开始后禁止主动切题，只允许完成当前题后自动顺序进入下一题。
- Flyway V19 新增录制会话、按题媒体分段和时间轴事件表。
- 管理端支持按题加载受保护的录音或视频，并将题目、回答、追问和过渡事件与媒体时间对齐。
- 点击时间轴事件可定位到对应题目的媒体时刻。
- 媒体内容不写入 MySQL，也不常驻 Java 堆；文件流式写入媒体目录，数据库仅保存元数据和关联关系。

### 2.4 缺陷修复

- 修复首次选择视频面试后摄像头状态显示已开启、但预览仍为黑屏的问题。
- 修复管理端已保存 DeepSeek API Key，但报告生成仍提示未配置 `DEEPSEEK_API_KEY` 的问题。
- 大模型调用现在优先读取管理端已启用且设为文字默认的数据库 Provider，环境变量作为兼容兜底。
- 修复刷新后倒计时重置、题目位置丢失、追问任务重复创建和网络失败后答案被清空的问题。

### 2.5 P0 安全、监控与交付基线

- 增加 Spring Boot Actuator 与 Prometheus 指标端点，Actuator 仅监听容器内部 8081 端口。
- 增加 AI 任务待处理数、运行数、失败数和最老待处理任务时长指标。
- 上传文件增加文件签名、MIME 一致性、文件名净化和可选 ClamAV 扫描。
- 媒体元数据、内容读取和下载增加所有者鉴权；下载使用附件响应。
- 媒体 SHA-256 改为流式计算，单题录制默认上传上限统一为 100MB。
- 增加 MySQL 与 `media_data` 备份脚本、完整性校验脚本和 P0 运维手册。
- 增加 GitHub Actions 质量门禁，覆盖 Maven 测试、React 构建和 Compose 配置校验。

### 2.6 Flyway 与数据库文件治理

- 明确 `backend/src/main/resources/db/migration/` 为唯一有效 Flyway 迁移目录。
- Flyway V17 优化模拟面试追问提示词，并保护管理员自定义的启用版本。
- Flyway V18 持久化面试当前进度。
- Flyway V19 增加面试方式、录制分段和事件时间轴结构。
- 旧初始化 SQL、历史迁移副本和手工执行脚本统一归档到 `docs/database/archive/`。
- 后续数据库结构变更从 V20 开始，不修改已经发布的迁移文件。

### 2.7 前端品牌与界面规范

- 前端显示名称由 `InterviewOS` 统一调整为 `AInterview`。
- 登录页主标题调整为“每一面，都算数。”。
- 全站标题与副标题（`h1`–`h6`），以及“管理工作台”等使用 `text-[var(--accent)]` 的文本栏目标题统一使用 `SourceHanSerifCN SemiBold` 字体族，并保留中文衬线字体回退。
- 文本栏目标题颜色统一为 `#7d4929`；正文、强调文字、按钮、标签、图标、输入框、文本域和选择器保持项目默认样式。
- 候选人端、管理端、登录页和面试页文案统一为正式、简洁的中文表达。
- 图标统一沿用 Lucide 矢量图标，并按具体业务语义重新映射，减少重复装饰图标。

## 5. 已知风险与待处理事项

- 前端主 JavaScript 包约 728KB，Vite 仍提示超过 500KB，后续需要路由级懒加载和模块拆分。
- `UserRole` 与 `RolePermission` 是无单列主键的关联表，MyBatis-Plus 启动时仍提示不能使用 `ById` 方法；应补充复合键策略或明确限制 Mapper 调用。
- 视频录制会持续占用 `media_data`，生产上线前需要核算并发、单场时长和保留周期，并设置容量告警和清理策略。
- 浏览器强制关闭时，尚未结束的当前录制分段仍可能丢失；需要在端到端验收中覆盖异常退出提示和重进恢复。
- KMS、安全组、强制 ClamAV、Prometheus/Grafana/Alertmanager、OSS 异地备份和隔离恢复演练仍需云服务器或云账号权限执行。

## 7. 发布验收重点

V18–V19 正式发布时至少完成以下人工验证：

1. 第 3 次追问后的回答只出现收尾语并进入下一题，不再生成追问。
2. 首次进入视频面试即可看到摄像头画面，不需要退出重进。
3. 文字面试不录制且不自动朗读；语音和视频面试只能顺序完成题目。
4. 语音与视频分段能够上传，并在管理端按题播放和按事件定位。
5. 刷新页面后题号、倒计时、追问次数和未完成 AI 任务可以恢复。
6. 管理端数据库 Provider 能直接用于提问、评分和报告生成。
7. Flyway 历史显示 V19，应用健康、HTTPS、OpenTalking 和 TURN 均正常。
