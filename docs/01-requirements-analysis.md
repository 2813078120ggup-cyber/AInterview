# AI 多模态智能模拟面试评测平台：需求分析（第一阶段）

## 1. 建设目标与边界

建设可部署的企业级模拟面试平台，支持管理端配置招聘资产、候选人完成多模态 AI 面试、面试官复核评价和平台生成可追溯报告。

本项目不将 DeepSeek、OpenTalking TTS/STT、邮件或短信等第三方凭据暴露至浏览器；AI 调用、媒体校验与报告生成由后端执行并记录必要审计信息。浏览器负责设备采集和按题分段上传，OpenTalking 独立提供虚拟人 WebRTC 媒体；公网环境所需 STUN/TURN 属于部署边界。

## 2. 角色与权限

| 角色 | 核心权限 | 默认入口 |
| --- | --- | --- |
| 管理员（ADMIN） | 用户、角色、岗位、题库、面试、报告、统计、系统配置和学习资料全量管理 | 管理工作台 |
| 面试官（INTERVIEWER） | 查看被分配面试、启动/结束面试、查看答案、人工评分与确认报告 | 面试工作台 |
| 候选人（CANDIDATE） | 查看本人面试、进入面试间、文本/音频/视频作答、查看已发布报告和获授权的学习资料 | 我的面试 |

权限采用 RBAC：用户与角色多对多；接口由 Spring Security 方法级授权和业务归属校验双重控制。学习资料额外通过用户/角色授权、资料发布状态和批注所有者校验访问范围。

## 3. 核心业务流程

1. 管理员维护岗位、题库分类与题库；可创建或审核 AI 生成题目。
2. 管理员创建面试，指定候选人、面试官、岗位、时间、时长和题目策略。
3. 面试官在时间窗口内开始面试；候选人进入独立面试间。
4. 候选人提交文字、录音或视频答案；服务端保存原文件、转写结果和结构化答案。
5. AI 根据岗位能力模型、题目、回答和转写文本完成评分、追问与总结；失败任务可重试且保留错误记录。
6. 面试结束后，面试官可人工复核；系统生成报告，管理员/面试官发布，候选人仅查看已发布报告。
7. 管理员查看按岗位、题库、时间、候选人维度统计的数据看板。
8. 候选人提交面试故障、功能建议或 BUG 工单；管理员转派、回复并推进状态，双方通过持久化站内通知和工单时间线协作。
9. 管理员上传和发布学习资料 PDF，按用户或角色授权查看/批注；候选人在权限范围内在线阅读、做高亮和个人笔记。

## 4. 功能清单与验收标准

| 模块 | 必须能力 | 完成判定 |
| --- | --- | --- |
| 认证与 RBAC | 登录、注册、刷新令牌、退出、密码加密、接口授权 | 三种角色不可越权访问接口与页面 |
| 用户/角色/岗位 | 分页查询、增改停用、角色分配、岗位能力模型 | 所有写操作落库并记录操作人 |
| 题库 | 分类、题库、题目、难度、标签、导入/AI 生成 | 可按岗位和标签选择有效题目 |
| 面试 | 创建、改期、取消、开始、结束、历史查询 | 状态机与参与人校验正确 |
| 面试间 | 题目编排、倒计时、自动保存、文字/音频/视频作答 | 重新进入可恢复已保存答案 |
| AI 服务 | 出题、追问、转写、TTS、评分、评价、总结 | 请求可追踪、失败可重试、结果可人工覆盖 |
| 报告与统计 | 报告生成/发布/PDF、历史记录、统计分析 | 候选人仅见已发布的本人报告 |
| 反馈工单 | 草稿、提交、截图、双向留言、管理员转派、状态流转、关闭终态 | 候选人仅见本人数据；管理员可处理全部工单；关闭后服务端拒绝留言和上传 |
| 站内通知 | 通知列表、未读数量、单条/全部已读、业务跳转 | 跨浏览器和设备持久化，重复业务事件不产生重复通知 |
| 学习资料 | 管理员上传 PDF、发布/下线、按用户/角色授权、下载开关；候选人 PDF 阅读、翻页缩放、高亮、便签和笔记 | 未授权用户不能从列表、详情、内容、下载或批注接口读取资料；批注按资料版本和用户隔离 |
| 运维 | OpenAPI、健康检查、日志、Docker Compose、Nginx | 新环境可按文档启动并通过健康检查 |

## 5. 非功能性要求

- 安全：BCrypt 密码、JWT 短期访问令牌、敏感配置环境变量化、上传类型/大小校验、审计日志。
- 数据：MySQL 8 外键与索引；软删除字段使用 `NULL` 表示未删除；所有时间使用统一时区策略。
- 性能：列表接口分页；AI、转写、视频分析和 PDF 生成异步化；Redis 用于缓存、限流和任务状态。
- 可观测性：统一错误码、请求 ID、结构化日志、Actuator 健康检查。
- 测试：关键 Service 单元测试、Controller 集成测试、权限回归测试和前端构建测试。

## 6. 数据与初始化要求

保留既有核心表，并通过 Flyway 持续补充岗位、题库分类、媒体文件、AI 会话/任务、操作审计、刷新令牌、录制时间轴、算法练习、反馈工单、站内通知和学习资料所需结构。当前代码库最新迁移为 V26，下一次结构变更从 V27 开始。

初始化数据目标：管理员 5 人、面试官 20 人、候选人 100 人；Java 300 题、前端 300 题、算法 200 题、数据库 200 题、AI 100 题；100 场合理的模拟面试及关联答案、评价和报告。所有初始密码使用 Spring Security BCrypt。

## 7. 当前工程差距

当前工程已具备 React 前端、Spring Security、题库/面试/录制/报告、DeepSeek 异步任务、OpenTalking、算法判题、反馈工单、站内通知、学习资料 PDF 阅读与批注、Flyway、Docker/Nginx、Prometheus 和后端测试。相较成熟企业级系统，下一阶段重点是：隔离主后端与 Docker 判题权限、补充前端组件与端到端测试、完善依赖/镜像/密钥供应链门禁、落地告警与分布式追踪、将媒体迁移到受控对象存储并完成异地备份和恢复演练。

## 8. 当前架构约束

系统继续采用模块化单体：MySQL 保存最终业务状态，Redis 承担限流和异步协调，本地私有媒体卷作为当前实现并保留迁移至 OSS/S3 的边界。第三方 AI、短信、邮件和 OpenTalking 凭据仅在服务端配置；浏览器只访问同源 `/api` 与 `/opentalking`。学习资料 PDF 不放入前端 `public/` 或构建产物，PDF.js 仅在获得后端授权后读取内容。
