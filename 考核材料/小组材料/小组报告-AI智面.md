## 1. 需求概述

面向高校求职场景的 AI 模拟面试评测系统。候选人在平台上预约并完成模拟面试（文字/语音作答），系统对作答进行多维感知分析并生成可追溯的评测报告；HR/管理员维护题库、查看报告并复核。

核心需求：
1. **共同业务闭环**：登录 → 预约面试 → 作答存储 → 换角色（HR/管理员）查询记录，前后端与数据库真实联动；
2. **感知模块一（语音分析）**：对录音作答分析语速、流利度、情绪稳定性、清晰度，接入评分引擎；
3. **感知模块二（文本理解与评价）**：对文字作答做语义理解与分档评价，接入评分引擎；
4. **可追溯评测报告**：两个感知结果进入评分规则，报告可追溯输入数据与评分规则，未测维度显示"未评估"；
5. **扩展能力（简历与题目）**：简历解析生成技能画像，按画像智能组卷；
6. **安全与权限**：角色权限拦截、异常处理、密钥不落仓库。

## 2. 总体架构

```text
React 19 前端（nginx）
   │ /api 反向代理
Cloud Gateway（Spring Cloud Gateway, 8082）
   │ Eureka 服务发现
Backend 核心（Spring Boot 4, Java 17, 8080/8081）
   ├── MySQL 8.0（Flyway 迁移 v1–v49）
   ├── Redis 7（任务队列/缓存）
   ├── DeepSeek API（文本评分 / 报告生成 / 组卷）
   └── voice-analysis（独立 Python 3.11 服务, FastAPI + librosa）
         └── 共享 media_data 卷读取录音文件（webm → ffmpeg → wav）
```

- **评分引擎**：四维加权（专业 45% + 表达 20% + 逻辑 25% + 应变 10%），语音分为旁路增强维度；
- **可追溯设计**：`evaluation` 表含 `voice_evidence`（四维原始特征+权重规则）与 `text_evidence`（输入摘要、命中分档、原始分/校准分、评分规则版本）；
- **异步任务**：评分任务走 Redis 队列 + 心跳/重试，支持管理员重新评分。

## 3. 感知模块实现

### 3.1 语音分析（独立轻量 Python 服务）
- `voice-analysis-service`：FastAPI 暴露 `POST /v1/analyze`；librosa 计算有效语音掩码（动态阈值）、语速、停顿比、能量/音高变异系数；
- Java 侧 `VoiceAnalysisService` 按题目聚合 `interview_recording_segment` 录音段，解析本地音频路径（多段按时长加权融合）；webm 经 ffmpeg 转码后分析；
- 结果四维子分 + `voice_evidence` 写入 `evaluation`，报告页「逐题语音分析」逐题展示；未录音题目显示"未评估"。

### 3.2 文本理解与评价（语义评分引擎）
- DeepSeek 按分档规则（0-20 未回答 … 93-100 专家级）输出四维分与评语，校准后落库；
- `text_evidence` 结构化记录：输入文本摘要与长度、命中分档及定义、四维原始分与校准分、评分规则版本号；
- 报告页「逐题回答评价」展示档位徽章、四维子分、评语与"评价依据（可追溯）"。

### 3.3 融合评分与报告
- 四维文本分加权 + 语音分旁路增强，汇总至 `report`；
- 报告详情接口返回 `questionVoiceReviews` / `questionTextReviews`，前端逐题渲染，可追溯输入与规则。

## 4. 扩展能力：简历与题目
- 候选人上传简历 → 解析技能/项目画像 → HR 端按画像从题库智能选题组卷 → 关联面试计划；
- 现场可用新简历触发新组卷结果，满足"真实实现"判据。

## 4.1 拓展功能（超出考核要求的加分项）

在满足考核基本要求（2 个感知模块 + 1 个扩展能力 + 融合评分 + 业务闭环）之外，项目还沉淀了完整的"训练—求职—招聘"闭环产品能力，以下拓展功能均已真实实现并通过前端路由接线，可作为加分亮点：

| 拓展功能 | 能力说明 | 技术要点 |
| --- | --- | --- |
| 多模态面试 + AI 追问 | 支持文字 / 语音 / 视频三种作答；答题后可触发 AI 追问（最多 3 次） | 服务端题目快照、追问幂等任务键、切题/收尾丢弃迟到追问 |
| 数字人面试官 | 集成 OpenTalking 数字人，追问/讲评/收尾语以"只朗读"模式播报 | 朗读序列中断旧音频、45s 兜底释放朗读锁、OpenTalking 不可用时降级浏览器语音 |
| 算法练习与隔离判题 | Java 17 算法题练习，独立判题 worker 隔离执行，含可视化与错题本 | `algorithm-judge-worker` 独立服务、题目/提交/进度/判题状态机 |
| AI 助手与生成审计 | 站内 AI 助手 + AI 生成内容审计、追踪与治理 | `AiGenerationAudit`、生成上下文记录、管理端 AI 追踪/治理页 |

| 自由面试 | 不设题本的自由问答，简历文本提取辅助 | `freeinterview`、`ResumeTextExtractor` |
| AI 治理与敏感数据脱敏 | 招聘 AI 评估的敏感信息脱敏与治理 | `RecruitmentSensitiveDataRedactor`、AI 治理规则 |
| 安全与可观测体系 | 账号安全事件、操作审计日志、数据字典、Prompt 模板、AI Provider 配置、主题设置 | `OperationAudit`、`P0Metrics`、账号安全基础 |

## 6. 测试情况
- 正常用例：登录/预约/作答/评分/报告全链路；语音、文本两个感知模块换新输入可复现真实结果；
- 异常用例：非音频文件上传、超大文件、DeepSeek 超时降级（语音旁路失败不阻断主链路）、非法参数校验；
- 权限用例：候选人越权访问他人报告被 403 拦截；企业端越权访问被拒；
- 详见《测试结果.xlsx》与 `evidence/构建或自动化测试记录.txt`。

## 7. 风险与应对
| 风险 | 触发条件 | 影响 | 应对 | 责任人 |
| --- | --- | --- | --- | --- |
| 外部模型不可用 | DeepSeek 接口超时/限流 | 评分延迟或失败 | 重试+超时降级，任务可重新触发 | 高弨 |
| 语音分析服务崩溃 | 长音频/并发分析 | 语音维度缺失 | 旁路降级为"未评估"，不阻断评分 | 高弨 |
| 部署环境差异 | 端口/卷挂载冲突 | 服务启动失败 | docker compose 统一编排 + 健康检查 | 张嘉豪 |
| 录音格式兼容 | 浏览器产出 webm/opus | 分析失败 | ffmpeg 转码兜底 | 高弨 |
| 测试数据缺失 | 现场无有效音频 | 演示失败 | data/测试数据/ 自备样例音频与简历 | 武心怡 |
