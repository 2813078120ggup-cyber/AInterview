# 作业01 —— 需求与方案分析（乔佳琪 · 组员）

**课程：**《软件工程行业案例分析与实现》· 人工智能Ⅱ方向　**姓名：** 乔佳琪　**角色：** 组员（开发、部署）

## 1. 角色与目标
本人在小组中负责**扩展能力「简历与题目」的开发**（简历解析 + 智能组卷）、**部署脚本与环境配置模板**，以及部分前端页面。目标：现场上传一份新简历即可解析画像并生成组卷结果；项目按模板配置即可一键部署。

## 2. 项目主要业务流程（本人负责部分加粗）
1. **候选人上传简历 → 简历解析生成技能/项目画像** → 2. **HR 端按画像从题库智能组卷** → 3. 组卷题目关联面试计划 → 4. 候选人作答进入评分流程 → 5. 报告题目来源可查；
6. **部署链路**：`config/.env.template` 配置模板 → docker compose 一键拉起 → 健康检查。

## 3. 核心数据对象（≥2 个）
- **Resume / 简历画像**：解析出的技能标签、项目经历、教育背景，作为组卷的输入画像；
- **组卷记录（卷与题目的关联）**：记录一次组卷选择的题目集合、关联的面试计划与生成依据，保证"报告题目来源可查、现场可复现"。

## 4. 所选 AI 功能与验收标准（本人负责部分）
| 功能 | 验收标准 |
| --- | --- |
| 扩展能力：简历与题目 | 上传一份新简历 → 解析出技能画像 → 智能组卷生成题目列表；现场换新简历可复现 |
| 部署与配置 | 按config模板填写（占位符，不含真实密钥）→ docker compose up 一键启动全部服务 |

## 5. 架构方案与理由
- **简历解析**：解析服务提取结构化画像（技能/项目/学历），与题库标签匹配选题；选择"画像-标签匹配 + 大模型辅助生成"的混合方案，兼顾可控性与智能化；
- **智能组卷**：按岗位画像的技能分布从题库按难度/类型加权抽取，保证试卷覆盖度；组卷结果持久化，可追溯；
- **部署配置模板化**：所有密钥走 `.env` 占位符注入，镜像内不含密钥，满足"数据与密钥安全"检查项；docker compose 统一编排 6 个服务并带健康检查。
