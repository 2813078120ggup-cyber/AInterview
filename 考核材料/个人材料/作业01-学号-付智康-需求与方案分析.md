# 作业01 —— 需求与方案分析（付智康 · 组员）

**课程：**《软件工程行业案例分析与实现》· 人工智能Ⅱ方向　**姓名：** 付智康　**角色：** 组员（开发、数据库）

## 1. 角色与目标
本人在小组中负责**数据库设计与迁移维护**、**账号与安全模块**（密码找回、登录限流、验证码、账号安全事件），以及**通知中心**（站内通知、通知偏好、邮件降级）。目标：数据模型完整、迁移可追溯；账号安全边界清晰；通知可靠送达且失败不误报。

## 2. 项目主要业务流程（本人负责部分加粗）
1. 候选人注册/登录 → **验证码与登录限流** → 2. **密码找回（重置票据）** → 3. **账号安全事件记录** → 4. 管理员/HR 向候选人发送面试通知 → **站内通知（未读/已读）** → **通知偏好 + 邮件降级**；
5. **数据库层**：Flyway 迁移统一管理表结构（V1–V49），ER 图与数据字典对应实体。

## 3. 核心数据对象（≥2 个）
- **账号安全事件（AccountSecurityEvent）**：记录登录异常、密码重置等安全事件，支撑审计与风险追溯；
- **站内通知（Notification）**：通知内容、接收人、未读/已读状态、类型与阅读位置，支撑面试通知与工单联动；
- **通知偏好（NotificationPreference）**：候选人可配置接收方式（站内信/邮件），邮件发送失败时降级不阻断。

## 4. 所选 AI 功能与验收标准（本人负责部分）
| 功能 | 验收标准 |
| --- | --- |
| 账号与安全 | 密码找回流程走通（票据限时/一次性）；连续登录触发限流；安全事件落库可查 |
| 通知中心 | 管理员发通知→候选人收到站内信并显示未读；邮件发送失败时降级不误报"系统繁忙" |
| 数据库设计 | ER 图、数据字典与 Flyway 迁移脚本一一对应，可追溯表结构演进 |

## 5. 架构方案与理由
- **数据库设计**：采用 Flyway 版本化迁移（V1–V49），`evaluation` 表预留 voice/text evidence 字段支撑可追溯报告；ER 图与数据字典同步维护，保证"数据模型合理"；
- **账号安全**：图形验证码 + 验证码冷却 + 登录限流（Redis）+ 密码重置票据（限时、一次性），分层防护；
- **通知中心**：站内通知持久化 + 邮件发送 try/catch 降级（失败返回 sent=false 不再抛异常），保证"通知送达但异常不阻断主流程"。

内容可追溯到后续实现：`auth/`（验证码、密码重置、安全事件）、`notification/`（站内通知、邮件服务、通知偏好）、`db/migration/`（V1–V49 迁移脚本）等实际代码位置。
