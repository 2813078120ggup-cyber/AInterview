# 作业01 —— 需求与方案分析（杨旺鑫 · 组员）

**课程：**《软件工程行业案例分析与实现》· 人工智能Ⅱ方向　**姓名：** 杨旺鑫　**角色：** 组员（前端、测试）

## 1. 角色与目标
本人在小组中负责**前端页面**（候选人工作台、企业端招聘页面、登录/注册/忘记密码页），以及**接口联调测试与权限校验**、**功能回归测试**。目标：候选人/企业端核心页面可用、交互完整；后端接口与角色权限边界校验到位；核心链路回归无遗漏。

## 2. 项目主要业务流程（本人负责部分加粗）
1. **候选人登录/注册 → 进入候选人工作台** → 2. **查看岗位大厅、维护简历、提交申请** → 3. **企业端维护岗位、筛选申请、安排面试** → 4. 候选人作答 → 评分 → 报告；
5. **接口联调**：前端调用后端接口 → 校验返回与参数 → 6. **权限校验**：候选人/企业/管理员角色边界 → 7. **回归测试**：核心链路（预约→作答→评分→报告）回归。

## 3. 核心数据对象（≥2 个）
- **候选人申请（Application）**：候选人投递岗位的申请记录与状态流转，串联候选人端与企业端；
- **岗位（Position）**：企业发布的招聘岗位，含职责、要求与关联申请/人才库。

## 4. 所选 AI 功能与验收标准（本人负责部分）
| 功能 | 验收标准 |
| --- | --- |
| 前端页面 | 候选人工作台、企业端招聘页、登录/注册/忘记密码页可正常加载与交互，含加载/空/错误状态 |
| 接口联调与权限 | 前端调用后端接口返回正确；候选人越权访问企业/管理员接口被 403 拦截 |
| 回归测试 | 预约→作答→评分→报告核心链路回归通过，与《测试结果.xlsx》一致 |

## 5. 架构方案与理由
- **前端页面**：React 19 + TypeScript + Tailwind CSS，复用 Radix UI 组件保证可访问性与状态反馈；页面按角色路由懒加载，同源 `/api` 代理；
- **接口联调**：以角色权限边界为测试重点（后端鉴权是数据安全边界），覆盖候选人/企业/管理员三类角色的越权场景；
- **回归测试**：在武心怡功能用例基础上做核心链路回归，保证"换新输入可复现真实结果"的验收判据。

内容可追溯到后续实现：`frontend-react/src/pages/`（candidate-workspace、company-*、login/register/forgot-password 等页面）、接口联调与回归测试记录等实际代码位置。
