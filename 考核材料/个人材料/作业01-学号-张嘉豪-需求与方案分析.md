**课程：**《软件工程行业案例分析与实现》· 人工智能Ⅱ方向　**姓名：** 张嘉豪　**角色：** 组长（统筹分工、迭代开发、部署）

## 1. 角色与目标
本人在小组中担任**组长**，负责：项目统筹与分工管理、迭代计划推进、Docker Compose 部署与网关配置、共同业务闭环（登录/预约/存储/角色查询）开发，以及 README 与小组报告的汇总。目标：保证系统按验收流程（启动→预约→感知→报告→越权拦截）完整可演示。

## 2. 项目主要业务流程
1. 候选人注册登录 → 预约模拟面试（选题库与时间）→ 进入面试作答（文字/语音）；
2. 作答数据落库 → 触发 AI 评分任务（Redis 队列异步执行）→ 感知模块分析（语音分析 / 文本理解与评价）→ 融合评分生成报告；
3. 候选人查看报告（逐题语音/文本可追溯区块）；HR/管理员切换角色查看记录、复核报告、维护题库；
4. 管理员可重新评分；越权访问被权限层拦截。

## 3. 核心数据对象（≥2 个）
- **Interview / InterviewQuestion（面试与面试题目）**：记录面试状态机（进行中/已完成/报告就绪等）、题目快照（含题干、选项、分值）、候选人作答与录音段关联；
- **Evaluation（逐题评测）**：四维分数（专业/表达/逻辑/应变）、总分、评语、`voice_score`/`voice_evidence`（语音感知证据）、`text_evidence`（文本理解证据），是"可追溯评测报告"的核心载体；
- **Report（综合报告）**：聚合逐题评测的加权总分与总结、优势、改进建议。

## 4. 所选 AI 功能与验收标准
| 功能 | 验收标准 |
| --- | --- |
| 感知模块一：语音分析 | 现场换新录音输入，系统调用语音分析服务返回真实四维子分并写入报告；未录音题目显示"未评估" |
| 感知模块二：文本理解与评价 | 现场换新文本输入，评分引擎按分档规则输出四维分与评语，报告可追溯输入摘要与规则版本 |
| 扩展能力：简历与题目 | 上传新简历可解析画像并生成组卷结果 |
| 共同业务闭环 | 登录、预约、存储、换角色查询全部走通，前后端与数据库真实联动 |

## 5. 架构方案与理由
采用 **Spring Boot 微服务 + React 前端 + Docker Compose 编排**：
- **微服务拆分**：Cloud Gateway 统一入口 + Eureka 服务发现，便于权限集中与扩展；语音分析拆为独立 Python 服务（librosa 生态在 Python 最成熟），通过内网 HTTP 调用、共享媒体卷读文件，语言各取所长；
- **异步评分**：Redis 队列 + 心跳重试，评分耗时不阻塞用户操作，失败可重新触发；
- **可追溯设计**：感知结果以 evidence JSON 落库（而非只存分数），满足"报告能追溯输入和评分规则"的验收硬性要求；
- **Docker 一键部署**：6 个服务统一编排 + 健康检查，保证现场验收可按 README 复现启动。

内容可追溯到后续实现：上述架构对应 `docker-compose.yml`、`cloud-gateway/`、`voice-analysis-service/`、`backend/.../evaluation` 等实际代码位置。
